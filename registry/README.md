# Публичный реестр

Каждый файл — запись о сущности. Имя файла — её идентификатор.

Отсканировав марку, вы получаете идентификатор. По нему открывается запись
отсюда: `registry/<entity-id>.json`.

## Что здесь есть, а чего нет

**Есть:** факт, время, участники в виде идентификаторов, ссылки на доказательства
в виде хэшей.

**Нет и не будет:** персональных данных, содержимого документов, коммерческих
условий. Запись доказывает, что документ с точно таким содержимым существовал
на указанную дату, **не храня сам документ**. Проверить может любой: посчитать
SHA-256 своей копии и сравнить с записью.

## Почему это временно

Сейчас реестр статический — обычные файлы в git. Это осознанно: цепочка
«марка → идентификатор → запись» работает уже сегодня, без сервера.

Чего пока нет: подписей, независимой проверки, отметок времени от третьей
стороны. Поэтому у записей `proof_level: PL-0` — заявление владельца, а не
доказательство, подтверждённое кем-то ещё. Git при этом даёт неплохую отправную
точку: история коммитов сама по себе фиксирует, когда запись появилась, и её
нельзя незаметно переписать.
