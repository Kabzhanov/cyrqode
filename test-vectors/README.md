# Тестовые векторы канонизации Circle Mark

Этот каталог содержит **самодостаточные** тестовые векторы для проверки
любой реализации канонизации JSON по RFC 8785 (JCS), совместимой с Circle
Mark. Они не зависят от Python-кода в `sdk/python` — тот код лишь один из
способов их получить и один из способов их проверить.

## Файлы

- `canonicalization.json` — массив тестовых случаев `{name, description,
  input, canonical, sha256}`.
- `verify.py` — скрипт, который прогоняет `canonicalization.json` через
  референсную Python-реализацию (`sdk/python/circlemark_canonical.py`) и
  дополнительно (опционально) валидирует `examples/*.json` по схемам из
  `schemas/`.

## Формат одного тестового случая

```json
{
  "name": "key_sorting_flat",
  "description": "человекочитаемое описание, что именно проверяет случай",
  "input": { "b": 2, "a": 1, "c": 3 },
  "canonical": "{\"a\":1,\"b\":2,\"c\":3}",
  "sha256": "e6a3385fb77c287a712e7f406a451727f0625041823ecf23bea7ef39b2e39805"
}
```

- `input` — уже разобранное JSON-значение (объект/массив/строка/число/
  булево/`null`). Ваш код должен взять именно эту распарсенную структуру
  (или эквивалент на вашем языке — dict/map/struct) и канонизировать её.
- `canonical` — ожидаемая каноническая строка, **как текст** (для удобства
  чтения глазами и сравнения построчно). При сравнении сопоставляйте байты
  UTF-8 этой строки, а не JSON-escaped форму, в которой она лежит в файле.
- `sha256` — `SHA-256` от **байтов UTF-8** строки `canonical`, в виде
  hex-строки в нижнем регистре (64 символа).

## Как использовать при написании своего SDK

1. Реализуйте функцию `canonicalize(value) -> bytes`, следуя
   `spec/canonicalization.md`.
2. Для каждого случая из `canonicalization.json`:
   - распарсите JSON-документ целиком через ваш стандартный JSON-парсер;
   - возьмите поле `input` как разобранную структуру;
   - вызовите вашу `canonicalize(input)`;
   - сравните результат **побайтово** (UTF-8) со значением поля
     `canonical`;
   - посчитайте `SHA-256` от результата и сравните hex-строку с полем
     `sha256`.
3. Все случаи должны совпасть **точно**, без исключений типа "почти
   совпадает" — расхождение даже в один пробел или порядок ключей означает,
   что подпись, посчитанная по вашей канонизации, не будет проверяться
   реализациями других участников экосистемы Circle Mark.
4. Отдельно обратите внимание на случай `rfc8785_french_reference_vector` —
   это независимо проверяемый эталонный вектор из публичного тестового
   набора RFC 8785/JCS (т.н. "French" vector), а не придуманный для этого
   репозитория пример. Если ваша реализация сходится с ним, это сильный
   сигнал совместимости с эталонным JCS-поведением, а не только с этим
   репозиторием.

## Что специально покрыто набором

- сортировка ключей объекта (плоская и во вложенных объектах);
- сохранение порядка элементов массива;
- юникод/кириллица без `\u`-экранирования;
- числа: целые (в т.ч. отрицательные и ноль), дробные, `-0`, экспоненциальная
  запись и пороги переключения на неё;
- булевы значения и `null`;
- пустой объект и пустой массив;
- экранирование кавычек, обратного слэша, переводов строк и прочих
  управляющих символов; отсутствие экранирования `/`.

## Чего в наборе нет (сознательно)

- Векторов для подписи/`crypto_suite` — конкретный алгоритм подписи ещё не
  выбран владельцем протокола (см. `schemas/event.schema.json`, поля
  `crypto_suite`/`signature`, и `spec/canonicalization.md`, раздел "Что
  закладывается на будущее"). Набор проверяет только канонизацию и хэш,
  которые не зависят от выбора алгоритма подписи.
- Векторов для CBOR/COSE-профиля — вне рамок v0.1.

## Проверка референсной реализации

```bash
python3 test-vectors/verify.py
```

Скрипт возвращает ненулевой код завершения, если хотя бы один случай
канонизации разошёлся с ожидаемым значением. Если в окружении не установлен
пакет `jsonschema`, валидация примеров по схемам пропускается с явным
предупреждением — проверка самой канонизации при этом выполняется всегда и
является обязательной частью прогона.

## Первое, обо что спотыкаются

Соблазн реализовать канонизацию «в одну строку» средствами стандартной
библиотеки. В Python это выглядит так:

```python
json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
```

**Так делать нельзя.** На большинстве случаев результат совпадёт, и это самое
опасное: расхождение вылезет позже, на реальных данных. Конкретный пример из
вектора `mixed_realistic_event_fragment`:

| Значение | `json.dumps` | Правильно по RFC 8785 |
|---|---|---|
| `1.0` | `1.0` | `1` |

Числа канонизируются по правилам ECMAScript `Number::toString`, где дробное
значение без дробной части печатается как целое. Одна такая величина в событии —
и хэш разойдётся, а подпись не сойдётся.

Аналогичные расхождения дают сортировка ключей (по UTF-16 code units, а не по
code point) и представление очень больших и очень малых чисел.

Поэтому и нужны векторы: прогоните их до того, как начнёте подписывать события.
