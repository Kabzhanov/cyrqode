# Проверка совместимости

Как убедиться, что ваша реализация совместима с чужими. Один запуск, три
проверки, понятный критерий.

## Зачем это нужно

Совместимость здесь держится не на договорённостях, а на побайтовом совпадении.
Событие сериализуется детерминированно, от результата берётся хэш, хэш
подписывается. Если ваша библиотека иначе сортирует ключи или иначе представляет
числа — подпись не сойдётся, и журнал отклонит событие.

Обнаружить это лучше сейчас, а не после того, как вы выпустите тираж меток или
раздадите свой SDK.

## Один запуск

```bash
python3 test-vectors/verify.py
```

Код возврата `0` — всё сошлось. Ненулевой — есть расхождение, и его нельзя
игнорировать.

## Что именно проверяется

**1. Канонизация — выполняется всегда.**
Основная гарантия репозитория, пропустить её нельзя. Правила — RFC 8785 (JCS),
векторы — `test-vectors/canonicalization.json`. Расхождение здесь означает, что
ваши события не примет ни один совместимый журнал.

**2. Подпись — если установлен `cryptography`.**
Два профиля: `ed25519-sha256-v1` (основной) и `ecdsa-p256-sha256-v1` (смарт-карты,
NFC secure element, HSM). Векторы — `test-vectors/signing.json`, референс —
`sdk/python/buip_signing.py`.

**3. Примеры против схем — если установлен `jsonschema`.**
Файлы из `examples/` валидируются по `schemas/`.

Если пакет не установлен, проверка помечается как **SKIP** — явно, а не «тихо
успешно». Так что `0` при двух пропущенных проверках означает ровно одно:
канонизация в порядке, остальное вы не проверяли.

Чтобы прогнать всё:

```bash
pip install cryptography jsonschema
python3 test-vectors/verify.py
```

## Как проверить именно свою реализацию

Скрипт проверяет референс. Чтобы проверить **себя**, сравнивайте с векторами
напрямую:

1. Возьмите вход из `test-vectors/canonicalization.json`.
2. Прогоните через свою канонизацию.
3. Сравните с ожидаемым результатом **побайтово** — не «визуально одинаково», а
   `==` на байтовых строках.

То же с подписью: ваша подпись того же события тем же ключом должна давать тот же
результат, что в `test-vectors/signing.json`.

Для генератора и сканера меток есть отдельная проверка:

```bash
cd tools && python3 test_cm_roundtrip.py -v
```

Хорошая приёмка — перекрёстная: ваш генератор → наш декодер, наш генератор → ваш
декодер. Обе стороны должны сойтись.

## Частые причины расхождений

- **Сортировка ключей.** JCS требует сортировку по кодовым точкам UTF-16, а не по
  байтам UTF-8 и не по алфавиту вашей локали.
- **Числа.** Целое, записанное как `1.0`, и целое `1` дадут разные байты.
- **Экранирование строк.** Юникод не должен превращаться в `\uXXXX`, где этого не
  требует стандарт.
- **Хвостовые пробелы и перевод строки.** Канонический вид не содержит ни того,
  ни другого.

## Версии и пины

Версия 0.x — черновик, схемы ещё могут ужесточаться. Пишете свой SDK —
привязывайтесь к **конкретному коммиту**, а не к «последней версии». Правила
совместимости, вступающие с 1.0, описаны в
[`spec/versioning.md`](../spec/versioning.md).
